# 노트북에서 실제 모델로 시연하기

**Git 복제 후에는 모델을 별도로 복사하고 실행 환경을 설치해야 합니다.** 아래의 설치 완료·바탕화면 경로는 최초 개발 노트북의 기록이며, 다른 PC에서는 저장소를 복제한 폴더에서 실행합니다. 가중치는 `models/README.md`에 안내된 위치에 둡니다.

갱신: 2026-10-14

현재 노트북에서 **받은 ONNX 모델 + 웹캠/영상 입력 + FastAPI + React 웹**으로 동작합니다. 최종 라즈베리파이 배치 전에 같은 위험 판정 코드를 노트북 CPU에서 확인하는 시연입니다.

## 바로 실행

프로젝트: `C:\Users\user\Desktop\2026\SSU\AIOT`

1. `start-ai-demo.cmd`를 더블클릭합니다. 현재 노트북에는 실행 환경이 설치돼 있습니다.
2. 자동으로 열린 웹에서 **웹캠 시작** 또는 **영상으로 분석**을 선택합니다.
3. 입력 미리보기의 박스와 아래 아기·위험 상태를 확인합니다. 아기가 없으면 ‘미감지 / 판단 불가’가 정상 동작입니다.
4. 분석을 멈추려면 웹의 **분석 중지**를 누릅니다.
5. 웹·서버까지 종료하려면 실행한 터미널에서 `Ctrl+C`를 누릅니다.

터미널로 실행하려면:

```powershell
cd "C:\Users\user\Desktop\2026\SSU\AIOT"
npm.cmd run demo:ai
```

기본 주소는 `http://127.0.0.1:5173/`입니다. 다른 프로그램이 포트를 쓰면 실행기가 빈 포트를 골라 주소를 출력합니다. 같은 실제 모델 데모가 실행 중이면 기존 웹을 엽니다. 기본 API는 8000이며 사용 중이면 8001~8004 중 빈 포트를 사용합니다. 모든 서비스는 이 노트북의 루프백 주소에만 엽니다.

**환경변수 파일을 바꿀 필요가 없습니다.** 실행기가 자신이 시작하는 웹에만 `agaeye` 모드, `laptop-demo` 기기 ID, 로컬 분석 표시를 적용합니다. 기존 `.env.local`이나 Pi 연결 설정을 덮어쓰지 않습니다.

## 입력 고르기

- **웹캠:** 기본값 0입니다. 연결되지 않으면 웹캠 선택에서 1 또는 2를 선택합니다. 다른 프로그램이 카메라를 사용 중이면 종료한 뒤 다시 시도합니다.
- **영상:** MP4·AVI·MOV·MKV·WEBM, 최대 512MB를 선택할 수 있습니다. 영상은 로컬 서버에 복사되고 노트북에서 분석합니다. 한글 파일명도 업로드 후 내부 파일명으로 처리합니다.
- 한 번에 한 입력만 분석합니다. 다른 입력으로 바꾸려면 먼저 중지합니다.
- ‘입력 화면 접기’로 미리보기를 숨길 수 있습니다. 이 미리보기는 현재 입력이며 **위험 확정 순간 사진과 별개**입니다.
- 영상은 재생 시각에 맞춰 처리합니다. 끝나거나 중지하면 이전 정상 결과가 현재 상태로 계속 표시되지 않습니다.

## 받은 모델 파일

`aga-eye-model-v1.tar.gz`에서 아래 파일을 확인했습니다.

| 원본 | 프로젝트 위치 | 용도 |
| --- | --- | --- |
| `models/agaeye_A_original_320_aug.onnx` | 동일한 `models/` 경로 | 실제 데모 추론 |
| `runs/train/A_original_320_aug/weights/best.pt` | `models/checkpoints/A_original_320_aug_best.pt` | 추가 내보내기용 원본 |
| `results/summary.csv` | `docs/model-artifacts/summary.csv` | 전달받은 학습·평가 결과 |

입력은 `[1, 3, 320, 320]`, 클래스는 `supine`, `side`, `prone`, `airway_visible`, `airway_covered`입니다. ONNX는 이미 변환돼 있어 추가 변환 없이 사용합니다. 파일 크기·SHA-256·압축 내 원본 경로는 [MANIFEST.json](model-artifacts/MANIFEST.json)에 남겼습니다. `.pt` 파일은 데모 실행에서 읽지 않습니다.

## 실행 구조와 수정할 파일

| 파일 | 역할 |
| --- | --- |
| `scripts/start-ai-demo.mjs` | 모델 사전 확인 → 로컬 API → Vite 시작, 기존 데모 재사용, 전체 종료 |
| `scripts/laptop_api.py` | 웹캠/영상 시작·중지, 영상 업로드, 입력 미리보기. 원본 FastAPI의 이벤트·SSE·확인 API 재사용 |
| `scripts/laptop_edge.py` | CPU 전용 ONNX 추론, 입력 시간 맞춤, 미리보기 저장, 종료 시 분석 불가 처리 |
| `configs/laptop-demo.yaml` | 노트북 전용 추론·시간 기준 |
| `src/components/LaptopDemo.tsx` | 실제 분석 제어·입력 미리보기 |
| `src/data/agaEyeSource.ts`, `agaEyeMapping.ts` | 원본 저장소 API → 화면 데이터 변환 |
| `vendor/aga-eye/` | 원본 커밋 `65d672cb`의 실행 코드. `SOURCE.json`·MIT `LICENSE` 포함 |

노트북 설정은 CPU 스레드 2개, 추론 목표 초당 3회입니다. 실제 속도는 입력과 노트북 부하에 따라 달라집니다. 위험 확정은 5초, 정상 지속 후 종료는 3초, 짧은 누락 허용은 1초입니다. 서버가 내려주는 위험 기준 시간이 우선합니다. 설정은 시연용이며 성능 합격을 의미하지 않습니다.

웹은 로컬 데모에서 라즈베리파이 대신 ‘노트북 분석’으로 표시합니다. 최종 Pi 연결은 기존 `agaeye` 모드와 [모델 연결 안내](MODEL_INTEGRATION.md)를 사용합니다.

## 다른 팀원 노트북에서 준비

Windows용 Python 3.11/3.12와 Node.js를 설치한 환경 기준입니다.

1. 팀 ZIP을 풀고 `npm.cmd ci`로 웹 패키지를 설치합니다.
2. `setup-ai-demo.cmd`로 `.venv-ai`와 고정된 CPU 실행 의존성을 설치합니다.
3. 위 ONNX 파일이 `models/`에 있는지 확인합니다.
4. `start-ai-demo.cmd`를 실행합니다.

다른 모델 경로를 사용하려면:

```powershell
npm.cmd run demo:ai -- --model "C:\모델폴더\다른모델.onnx"
```

기존 데모가 실행 중이면 먼저 그 터미널에서 `Ctrl+C`로 종료합니다. 아가 아이 5개 클래스와 메타데이터를 가진 ONNX인지 사전 확인하며 일반 객체 탐지 모델은 그대로 대체할 수 없습니다.

## ONNX·NCNN 변환

지금 ONNX 파일은 바로 사용할 수 있습니다. NCNN이 필요하면 모델 담당자의 Ultralytics/PyTorch 내보내기 환경에서 원본 체크포인트로 변환할 수 있습니다.

```powershell
python scripts/export-model.py --weights models/checkpoints/A_original_320_aug_best.pt --formats onnx ncnn --imgsz 320
```

도우미는 CPU를 지정하며 결과는 체크포인트 옆에 생성됩니다. 이번 작업에서 NCNN 변환은 실행하지 않았습니다. 현재 실행기는 ONNX Runtime용이므로 NCNN으로 실제 분석하려면 별도의 추론 어댑터를 추가해야 합니다. 원본 저장소에도 `vendor/aga-eye/scripts/export_model.py --formats onnx ncnn`이 있습니다.

## 검증한 범위

- 받은 ONNX를 CPU로 실제 실행: 5개 클래스·320 입력 확인, 합성 프레임 추론 성공.
- 합성 영상 업로드 → 실제 ONNX 처리 → 상태·입력 미리보기 → 중지까지 브라우저에서 확인.
- 노트북 웹캠 0으로 실제 모델 처리 및 웹 상태 갱신 확인. 확인 후 카메라는 중지했습니다.
- 재시작 후 입력 상태 복구, 중복 시작 차단(409), 390px에서 가로 넘침 없음.
- 단위 검사 36개, 기존 데모 브라우저 6개, 저장소 API 브라우저 3개, TypeScript·Vite 빌드 통과.

합성 영상은 배선·실행 확인용이며 아기 위험 탐지 정확도 시험이 아닙니다. 이번 노트북 시험으로 실제 영유아 환경의 정확도·위험 누락률·Pi 성능이 검증된 것은 아닙니다. 첨부 CSV는 전달받은 결과이며 여기서 재평가한 수치가 아닙니다.

현재 실제 데모를 켠 상태에서 다음 명령으로 합성 영상 연결 검사를 다시 실행할 수 있습니다. 웹에서 다른 입력 분석을 중지한 뒤 사용합니다.

```powershell
npm.cmd run test:laptop-ai
```

기존 모의 화면 검사는 5188, 저장소 규격 검사는 5174/8011을 사용해 실제 데모와 분리합니다. 검사는 순서대로 실행합니다.

## 저장되는 것과 현재 범위

- 업로드 영상·입력의 마지막 JPEG·분석 로그: 프로젝트의 `runtime/`에 저장됩니다. 업로드한 영상 파일은 직접 정리하기 전까지 남습니다.
- 위험 이벤트·위험 순간 JPEG·보호자 확인: 원본 개발 서버의 메모리에 있으며 전체 서버를 종료하면 사라집니다.
- 모의 데이터 모드의 브라우저 저장소와 실제 데모 이력은 구분됩니다.
- 팀 공유 ZIP에는 `runtime/`, `.venv-ai/`, `node_modules/`를 넣지 않습니다. 제공받은 모델과 실행·개발 문서는 포함합니다.
- 로그인·영구 DB·웹을 닫은 상태의 PUSH·실제 Pi 배포는 후속 작업입니다.
