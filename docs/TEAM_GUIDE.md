## 화면 구성

### 모니터링

상단 메뉴 아래에 아기의 현재 상태와 큰 알림 사진을 배치합니다. 연결 상태는 현재 상태 아래, 최근 이력은 그 다음에 나옵니다. 평소에는 지난 알림 사진을 보여주고, 위험이 발생하면 현재 위험 사진과 확인 버튼으로 바뀝니다. 모바일 위험 화면에서는 사진을 맨 먼저 표시합니다.

서버 연결은 노트북 API와 브라우저 간 통신입니다. 라즈베리파이 연결과는 별도로 표시합니다. 서버가 살아 있어도 라즈베리파이나 카메라가 끊길 수 있기 때문입니다.

### 위험 이력

날짜, 유형, 보호자 확인 여부로 필터링합니다. 행을 누르면 위험 시작·확정·종료·사진 촬영·보호자 확인 시각과 이벤트 ID를 확인합니다. 상세 창은 닫기 버튼이나 Escape 키로 닫을 수 있습니다.

### 사용 안내

상태를 읽는 방법과 확인·종료의 차이를 설명합니다. 기술적인 데이터 계약은 별도 문서에서 관리합니다.

## 왜 이렇게 구현했는지

| 결정 | 이유 |
| --- | --- |
| 모의 데이터와 API 연결 코드를 분리 | 모델 개발 일정과 무관하게 화면을 개발하고, 연결 시 화면 수정 범위를 줄이기 위함 |
| 공통 TypeScript 타입 정의 | 팀원마다 ‘정상’, ‘없음’, ‘분석 불가’를 다르게 해석하는 일을 줄이기 위함 |
| 카메라·서버·라즈베리파이 연결 분리 | 하나가 연결됐다는 이유로 다른 장치까지 정상이라고 표시하지 않기 위함 |
| 확인 기록과 위험 종료 분리 | 보호자가 버튼을 눌렀다는 이유로 실제 위험 판정을 해제하지 않기 위함 |
| 이벤트 ID로 병합 | 네트워크 재전송 때 같은 위험을 중복 기록하지 않기 위함 |
| 사진과 텍스트 경보 분리 | 사진 조회가 느려도 위험 경보가 먼저 표시되도록 하기 위함 |
| 마지막 수신·분석 시각 검사 | 오래된 정상 결과를 현재 상태처럼 보여주지 않기 위함 |
| 시스템 알림 대신 화면 내 경보 | 첫 버전을 웹을 열어 둔 환경으로 한정하고, PUSH 연동과 구분하기 위함 |

SSE는 서버에서 브라우저로 상태와 이벤트를 전달하는 연결입니다. 보호자 확인은 일반 POST 요청으로 저장합니다. 선택한 모델 저장소는 라즈베리파이에서 HTTP POST로 생존 신호·이벤트·사진을 전송합니다. 실제 형식과 실행 순서는 [모델 연결 안내](MODEL_INTEGRATION.md)에 정리했습니다.

## 상태 처리에서 지켜야 할 규칙

1. 입력 오류·분석 불가는 아기 미감지와 다릅니다.
2. 아기를 찾지 못했으면 위험 여부는 판단 불가로 표시합니다.
3. 데이터 수신 또는 분석 시각이 기본 12초 이상 오래되면 오래된 결과로 처리합니다. 이 값은 개발용 설정이며 성능 합격 기준이 아닙니다.
4. 연결이 끊겨도 종료가 확인되지 않은 위험 이력은 삭제하지 않습니다.
5. 위험 확인 버튼은 확인 시각만 기록합니다.
6. 이미 종료된 과거 이벤트는 이력에 추가하며 현재 긴급 경보로 전환하지 않습니다.
7. 사진 실패가 텍스트 경보를 막지 않아야 합니다.

## 5분 시연 순서

1. `npm run dev` 실행 후 모니터링 화면에서 ‘개발용 시나리오’ 제목을 눌러 펼칩니다.
2. ‘엎드림 위험’ → 경보·예시 이미지 확인.
3. ‘확인했어요’ → 위험이 유지되고 확인 기록만 바뀌는지 확인.
4. ‘동일 이벤트 재수신’ → 이력 수가 늘지 않는지 확인.
5. ‘서버 단절’ → 현재 상태가 판단 불가로 바뀌는지 확인.
6. ‘연결 복구’ → 종료되지 않은 위험이 다시 표시되는지 확인.
7. ‘위험 종료’ → 종료 시각 기록 확인.
8. 위험 이력에서 상세 창과 필터를 확인합니다.

## 홈 모니터 UI (2026-10-13)

사용자가 선택한 방향은 편안한 홈 모니터이며, 현재 상태와 위험 사진을 중심으로 구성했습니다. 밝은 중립색 바탕과 짙은 글씨를 사용하고, 상태에는 선명한 의미 색상을 적용합니다. 장식 그림과 반복되는 색상 카드는 추가하지 않았습니다.

- `src/App.tsx`의 `app-header`: 로고·메뉴·알림 버튼을 상단에 배치합니다. 기존 왼쪽 고정 메뉴는 사용하지 않습니다.
- `src/App.tsx`의 `home-monitor`: 아기의 현재 상태와 큰 알림 사진을 나란히 배치합니다. 아기 감지·위험 상태를 먼저 보여주고, 카메라·서버·라즈베리파이·분석 상태는 보조 정보로 표시합니다.
- `src/components/MonitorPhoto.tsx`: 현재 위험, 지난 알림, 종료 미확인, 로딩, 사진 없음 상태를 표시합니다. 현재 위험에서는 확인 버튼을, 지난 기록에서는 상세 보기 버튼을 표시합니다.
- 평소에는 이력의 가장 최근 사진을 표시합니다. 제목·종료 상태·촬영 시각·설명으로 과거 사진임을 명시하며, 현재 아기 모습이나 실시간 영상으로 표시하지 않습니다. 종료 미확인 이력은 별도로 알립니다.
- `src/components/Photo.tsx`: 사진 로딩·조회 실패·재시도를 담당합니다. 이미지 전체가 보이도록 `object-fit: contain`을 사용합니다. 모의 사진은 SVG 예시라는 표시를 유지합니다.
- `src/styles.css`: 화면 배치·색상·반응형 동작을 관리합니다. 주요 상태는 26~28px, 상단 상태 제목은 29~36px, 일반 설명은 14~16px입니다. 연결 상태의 값은 20px로 표시합니다.
- 모바일은 현재 상태 → 알림 사진 → 연결 상태 순서입니다. 위험이 발생하면 사진과 확인 버튼 → 현재 상태 → 연결 상태 순서로 바뀝니다.
- 최근 이력은 화면 아래의 목록으로 표시합니다. 오늘의 위험·미확인 건수는 제목 옆 또는 아래에 요약합니다. 전체 이력의 필터와 상세 창은 그대로 사용합니다.
- 개발용 시나리오는 기본으로 접혀 있으며, 제목을 누르면 펼쳐집니다.

상태·이벤트 병합, 보호자 확인, 위험 종료, 모델 연결 계약은 수정하지 않았습니다. 기존 브라우저 검사에 과거 사진의 제목·종료 표시·실시간 영상 아님 표시를 추가했습니다. 최신 화면은 `docs/screenshots/`에서 확인할 수 있습니다.

### 실행 파일의 중복 서버 처리

`start-local.cmd`는 먼저 5173 포트의 응답을 확인합니다. `index.html`의 `application-name=aga-eye-web`과 Vite 개발 클라이언트를 확인하면 기존 서버의 화면만 엽니다. 다른 웹 서비스가 응답하면 안내 후 종료하며, 프로세스를 강제 종료하지 않습니다. 응답이 없으면 기존과 같이 패키지를 준비하고 Vite를 실행합니다.

터미널에서 직접 사용하는 `npm run dev`의 기본 동작은 같습니다. 직접 실행한 서버를 종료하려면 해당 터미널에서 `Ctrl+C`를 누릅니다.
### 가독성 유지 기준

박스를 줄이더라도 설명 글씨를 10~11px로 축소하지 않습니다. 주요 상태는 굵게, 설명과 기록은 충분히 짙은 색으로 표시합니다. 상태 영역의 설명 길이가 달라도 마지막 갱신 시각은 같은 행에서 정렬합니다. 개발 패널이나 푸터를 포함해 작은 글씨는 기본 12px 이상을 유지합니다.
## 상태 색상 기준 (2026-10-14)

| 주의·미감지·응답 지연·종료 미확인 | 주황 | `#B45309` | `--amber` |
| 위험·장치 단절·입력 오류 | 빨강 | `#DC2626` | `--red` |
| 판단 불가·확인 중·종료된 기록 | 회색 | `#4B5563` | `--neutral` |

현재 상태 배지는 해당 색 바탕과 흰색 글씨로 표시합니다. 위험 사진의 테두리와 확인 버튼은 같은 빨강을 사용합니다. 지난 사진의 종료된 기록은 회색, 종료 미확인은 주황으로 표시합니다. 정상 상태값과 선택된 메뉴는 같은 초록을 사용합니다.

색상과 함께 상태 문구·아이콘을 유지합니다. 보호자가 확인하더라도 위험 판정이 유지되는 동안에는 위험 표시를 초록색으로 바꾸지 않습니다. 서버 응답 지연은 주황, 라즈베리파이 단절 점은 빨강으로 표시합니다. 배치와 글자 크기는 이번 색상 변경에서 수정하지 않았습니다.
## 선택한 모델 저장소 연결 (2026-10-14)

대상은 [wlsdn66597/aga-eye](https://github.com/wlsdn66597/aga-eye)의 `65d672cb` 커밋입니다. `.onnx` 가중치는 별도 준비가 필요하며 모델 실행은 Pi 담당자가 진행합니다. 프론트엔드의 기본 데모 실행은 유지했습니다.

- 연결 설정: `.env.agaeye.example` → `.env.local`, `VITE_DATA_MODE=agaeye`, `VITE_DEVICE_ID=crib-01`.
- 실제 데이터 경로: 노트북 FastAPI `/devices/{id}/status`, `/events`, `/stream`, 확인·사진 API.
- 서버의 Unix 초와 snake_case를 기존 화면 타입으로 변환합니다. 새 생존 신호만으로 오래된 추론 시각을 갱신하지 않습니다.
- 현재 위험 사진은 `active_event_id`로 선택합니다. 촬영 시각이 제공되지 않으면 미제공으로 표시합니다.
- 실행 순서, 저장소 기본 시간 값, 모델·서버 담당자가 추가해야 할 필드는 [모델 연결 안내](MODEL_INTEGRATION.md)를 확인합니다.
- 검사: 단위 검사 `npm.cmd test`, 기존 데모 `npm.cmd run test:e2e`, 저장소 연결 규격 `npm.cmd run test:agaeye`.

실제 노트북 FastAPI·웹캠·영상 연결을 추가로 확인했습니다. Pi 시험은 별도입니다. `test:agaeye`는 규격 서버 검사이며 실제 ONNX 연결 검사는 `test:laptop-ai`로 구분합니다.
